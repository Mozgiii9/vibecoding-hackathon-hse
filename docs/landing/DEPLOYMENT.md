# Независимое размещение лендинга

Владелец 25 октября 2026 отдельно разрешил публикацию лендинга на предоставленном сервере по IP. Это расширяет первоначальное условие передачи интегратору только для статического сайта. Приложение, тестовые среды A/B/C, firewall и их конфигурация не меняются.

## Структура своей среды

- `/srv/ryadom-hackathon/landing/releases/<SHA>/`: только содержимое `landing/`.
- `/srv/ryadom-hackathon/landing/current`: ссылка на выбранный выпуск.
- `/srv/ryadom-hackathon/landing/tools/node`: отдельная копия уже установленного Node 22.21.1 (Linux x64), без скачивания и изменения чужих tools.
- `/srv/ryadom-hackathon/landing/ryadom-landing.service`: собственный systemd unit, связанный через `systemctl link`.
- Порт 80, bind 0.0.0.0. До занятия порта обязательна проверка `ss -ltnp`; занятый порт не освобождать остановкой чужого процесса.

Процесс запускается с DynamicUser и единственной capability для bind порта 80. HTTP доступен без учётных данных; лендинг не принимает формы, не проксирует backend и не собирает пользовательские данные. Персональные данные в HTTP-приложение не передавать. Если появится домен или доверенный TLS-вход по IP, TLS настраивает владелец инфраструктуры отдельно.

## Первая установка

1. Прочитать `docs/agents/SHARED_SERVER.md`, осмотреть порты, ресурсы и существующие среды, не читая private/env. Владелец разрешил именно этот сервер; реквизиты не хранить в Git/CLI.
2. Собрать архив только `landing/`, проверить SHA256 и передать по SSH/SCP. В архив не включать `.git`, docs, node_modules, пользовательскую память и записи. Передачу проводить через stdin/SSH authentication, пароль не записывать в команду.
3. Распаковать в новый каталог собственного releases. Если каталог существует, не перезаписывать его. Сравнить SHA256 файла и список поставки. Выдать читаемые для DynamicUser права публичным файлам.
4. Создать собственный tools, скопировать системный/предоставленный Node runtime в него. Глобальные установки, build и STT не нужны. Если потребуется тяжёлая операция, сначала взять общий heavy.lock.
5. Скопировать поставляемый `ryadom-landing.service` в свой каталог, выполнить `systemd-analyze verify` для этого файла, затем `systemctl link` абсолютного пути к нему. Включить и запустить только `ryadom-landing.service`. Общие службы не перезапускать.
6. Проверить HTML, CSS, JS, SVG/PNG по публичному URL, код HTTP, отсутствие внешних запросов и работу сценария. Проверить, что `/.git/config`, `/README.md`, `/server.mjs`, `/config.js.bak` и неизвестные маршруты дают 404, POST даёт 405.
7. Только после успешной публичной проверки добавить реальный canonical, og:url и абсолютный og:image в исходник и опубликовать новый срез. Домен и URL приложения не придумывать.

## Обновление и откат

Выпуск immutable: подготовить новый каталог, проверить файлы, переключить только свою ссылку `current` атомарным rename и перезапустить только свой `ryadom-landing.service`. Предыдущий каталог сохранить. Для отката вернуть ссылку на предыдущий SHA и перезапустить свою службу. Не применять reset/force-push и не трогать среды команды.

## Headless-проверки

Используется уже установленный Playwright и Chrome, новые зависимости лендинга не нужны. Запустить локальный статический сервер, затем из корня этого worktree:

```sh
# Переиспользовать Playwright из существующей frontend-установки.
PLAYWRIGHT_MODULE=./app/builds/typescript/client_web/node_modules/playwright/index.mjs node docs/landing/run-checks.mjs
```

Если зависимости установлены в другом checkout, указать абсолютный путь к тому же модулю. `LANDING_BASE_URL` меняет проверяемый URL, `LANDING_EVIDENCE_DIR` меняет каталог артефактов. Runner открывает только headless Chrome. В проверках нет signup, API, провайдера или личных данных. Реальная готовность продукта проверяется командой отдельно.

## Оставшиеся входные данные от интегратора

- Подтверждённый публичный HTTPS URL обычного входа в MVP, без токенов и фиктивных preview. До него обе позиции CTA остаются состоянием ожидания.
- Итог приёмки единого audio UI/STT/evidence/confirm кандидата и его SHA.
- Реальные разрешённые screenshot/video синтетического прохода, без credentials. До них продуктовый кадр не подменять иллюстрацией, видео-кнопку не добавлять.
