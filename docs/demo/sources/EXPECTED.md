# Синтетические источники для показа

Только вымышленные данные. Цель и идентификаторы критериев совпадают с `docs/contracts/demo-fixture.json`: `cv` — одна отправка резюме, `mock` — два пробных интервью, `feedback` — одна правка по обратной связи. Для показа создать новую подтверждённую цель с этими критериями и пустым прогрессом. Файлы не являются заранее полученным ответом модели.

| Файл | Ожидаемые criterionId / eventType / точная цитата | После импорта | После ручного подтверждения |
|---|---|---|---|
| `01-plan.txt` | `cv` / `intention` / `Завтра хочу отправить резюме.` | 0 / 0 / 0 | 0 / 0 / 0: намерение не увеличивает счётчик |
| `02-completed-cv.txt` | `cv` / `completed_action` / `Сегодня отправил резюме.` | 0 / 0 / 0 | 1 / 0 / 0 |
| `03-mock-interview.txt` | `mock` / `completed_action` / `Провели первое пробное интервью.` | 1 / 0 / 0 | 1 / 1 / 0 |
| `04-obstacle.txt` | `mock` / `obstacle` / `Не могу провести второе пробное интервью: партнёр заболел.` | 1 / 1 / 0 | 1 / 1 / 0: препятствие не увеличивает счётчик |
| `05-feedback.txt` | `feedback` / `completed_action` / `Внёс правки в резюме по обратной связи.` | 1 / 1 / 0 | 1 / 1 / 1 |

Счётчики в таблице идут в порядке `cv / mock / feedback` и предполагают последовательное выполнение строк с подтверждением предыдущего действия. Пока карточка имеет `proposed`, её действие не засчитывается. Критерий `mock` пока не выполнен: 1 из 2. Если подтвердить действие, а затем отклонить его, соответствующий счётчик должен уменьшиться.

## Повтор без изменения текста

После подтверждения `02-completed-cv.txt` снова импортировать **этот же файл**, целиком, в ту же цель. Не создавать шестой похожий текст и не менять перевод строки. Ожидается `duplicate: true`, тот же source/evidence, без второго вызова extraction и без увеличения `cv`: остаётся 1. При ручном переносе в UI дважды вставить одну и ту же строку `Сегодня отправил резюме.` с одинаковыми пробелами и переводами строк. Заголовок не участвует в hash. Сходный смысл в другом тексте не доказывает автоматическую дедупликацию.

## Шестой источник: короткое аудио

`demo-audio.wav`, `demo-audio-transcript.json` и `audio-metrics.json` готовит владелец аудиопути. Они добавляются отдельно после реального STT. Наличие пяти текстов не доказывает работу аудио. Для аудио показывать фактическую расшифровку, точную цитату и времена только из настоящих STT segments; ожидаемый прогресс уточняется по фактическому содержанию записи. Не выдавать написанный сценарий озвучки за результат STT.

## Статус проверки

Таблица — ожидаемый сценарий, не журнал состоявшегося UI-прохода. Живые модельные результаты приёмочного корпуса записывает `docs/evaluation/run-context-evaluation.mjs`; полный UI / прогресс / повтор проверяет release-проход на интегрированном кандидате.
