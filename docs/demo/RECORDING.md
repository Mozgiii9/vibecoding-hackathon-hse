# Harness записи реального UI

Подготовлен [scripts/demo/record.mjs](../../scripts/demo/record.mjs), затем C записал два реальных текстовых прохода через обычный UI. Оба имеют `COMPLETED_TEXT`, `duplicate: false`, точную цитату, одно подтверждение и рост критерия интервью с 0 до 1. Ниже отдельно зафиксированы существующие записи и правила harness.

| Запись | Кандидат и фактический результат |
|---|---|
| [Dev WebM](defense/recordings/text-ef360ae/completed-text/demo.webm), [metadata](defense/recordings/text-ef360ae/metadata.json) | ef360ae, 25 октября 14:33 МСК, 1440×900, длительность видеопотока 15,04 с |
| [Production WebM](defense/recordings/production-eba453c/completed-text/demo.webm), [metadata](defense/recordings/production-eba453c/metadata.json) | eba453c, 25 октября 14:51–14:52 МСК, 1440×900, длительность видеопотока 16,12 с |

Для защиты основной короткий резерв — production-запись. Время `startedAt` / `finishedAt` в metadata включает запуск браузера и финализацию, поэтому отличается от длительности видеопотока. SHA в metadata передан оператором, его происхождение сохранено. **Полный трёхминутный ролик text+audio, обе человеческие репетиции и физический проектор остаются NOT_RUN.**

Основной MVP принят интегратором по [production evidence](evidence/c-production/summary.json). Аудио подтверждено отдельными семью чистыми UI-проверками C на eba453c; его нет в этих текстовых WebM. Независимая проверка A выполнена на ef360ae с идентичными перечисленными runtime-исходниками, со статусом audio `DIAGNOSTIC_RECOVERY_PASS`. Тест восстановления A дополнительно выполнен C на точном eba453c, PASS 1/1. Новый публичный HTTPS/TLS-сценарий для iPhone находится в работе, физический iPhone NOT_RUN. Это отдельная добавленная задача, её завершение здесь не заявляется.

## Что делает text-сценарий

1. Открывает установленный Chrome в headless-режиме, отдельный непостоянный browser context, кадр 1440×900. Приложение и серверы сам не запускает.
2. Проходит обычную форму `#identifier` / `#password` / «Войти» синтетическим аккаунтом. Автоматический local-owner вход, регистрация и обход авторизации не реализованы. При отсутствии обычной формы запись завершится ошибкой.
3. Проверяет настоящий ответ UI-запроса `/api/goals/demo`, подтверждённую цель «Подготовиться к ML-собеседованию» и ровно один критерий «Пройти пробные интервью» либо «Провести пробные интервью». **Цель и память должны быть подготовлены человеком заранее.** Скрипт их не создаёт, не очищает, не удаляет и не заменяет.
4. Через форму «Добавить контекст» импортирует одно синтетическое сообщение. Название содержит фактическое время, тело постоянно:

   > Синтетическая демонстрационная заметка Рядом. Сегодня провели одно пробное ML-интервью с наставником.

5. Дожидается реального HTTP-ответа импорта. Проверяет связь source / goal / criterion, ровно одно `completed_action`, диапазон точной цитаты и начальный статус `proposed` нового события. Невалидный ответ, неоднозначные события, отсутствие селектора, таймаут и ошибка провайдера завершают запись с `FAILED`. Подстановки, fixture и перехваты ответов не используются. Development preview запрещён.
6. Находит ровно одну строку соответствующего события, открывает источник через UI и проверяет настоящий source-ответ, заголовок и выделенную цитату. При совпадающих summary у нескольких строк останавливается, вместо выбора первой.
7. **Для нового источника** нажимает одну кнопку «Подтвердить» только у проверенного выполненного действия. Проверяет PATCH-ответ и серверный прогресс: рост ровно на единицу по нужному критерию. При неоднозначности ничего дополнительно не подтверждает.
8. **Для `duplicate: true`** открывает сохранённый источник, проверяет видимое уведомление о повторе и завершает с `DUPLICATE`. Не подтверждает, не отклоняет и не меняет статус повторно. Уникальное название не меняет content hash: повтор того же тела для той же цели честно возвращает сохранённый источник с прежним названием. Такой результат не считается новым вызовом модели.
9. Закрывает context, затем получает готовый WebM и пишет metadata с фактическими timestamp и проверенными шагами. Запись с ошибкой попадает отдельно в `failed/`. Статус `COMPLETED_TEXT` относится только к этому автоматическому текстовому проходу, а не к полному MVP или человеческой репетиции.

Наличие реального HTTP-ответа браузеру не доказывает внутренний вызов конкретного LLM-провайдера. Поэтому metadata сохраняет `providerCall: not-observable-from-browser`, а для повтора явно указывает, что новый вызов не заявляется. Живую конфигурацию модели отдельно проверяет интегратор.

## Параметры

| Environment | Назначение |
|---|---|
| `RYADOM_DEMO_URL` | Уже работающий UI: HTTPS или loopback HTTP, путь `/` либо `/login`, без credentials, query и hash |
| `RYADOM_DEMO_USERNAME` | Имя заранее созданного синтетического аккаунта |
| `RYADOM_DEMO_PASSWORD` | Пароль этого аккаунта. Не писать в команду, историю shell или Git |
| `RYADOM_DEMO_OUTPUT_DIR` | Необязательно. По умолчанию `output/playwright/ryadom-recordings`. Разрешены только подпути `output/` и `docs/demo/defense/recordings/` внутри репозитория, без symlink-выхода наружу |
| `RYADOM_DEMO_SHA` | Необязательно. Фактический SHA кандидата, 7–40 hex-символов. Сохраняется как `operator-provided`, скрипт не выдаёт его за независимо проверенный SHA сервера |
| `RYADOM_DEMO_TIMEOUT_MS` | Необязательно. Ожидание HTTP-ответа, по умолчанию 90000 мс, допустимо 5000–300000. Поиск селектора ограничен максимумом 20000 мс |

Для совместимости принимаются `USERNAME`, `PASSWORD`, `OUTPUT_DIR`, если соответствующие prefixed-переменные отсутствуют. Предпочтительны prefixed-имена. Значения системных `USER` / `LOGNAME` не используются. `RYADOM_DEMO_AUDIO_PATH`, если задан, намеренно останавливает запуск: аудиоавтоматизация пока не реализована.

Скрипт импортирует **уже установленный** `playwright` через `createRequire` из `app/builds/typescript/client_web/package.json`. Не использует `npx`, не устанавливает CLI или браузер. Если Chrome или пакет отсутствует, завершится ошибкой без установки зависимостей.

## Команды для оператора

Рабочая директория — корень этого репозитория. Перед каждой новой записью человек проверяет URL, синтетический аккаунт, подготовленную цель и SHA. Существующие выполненные запуски перечислены выше; команды ниже служат инструкцией повторного запуска.

```zsh
# Проверить синтаксис без запуска приложения или браузера.
node --check scripts/demo/record.mjs

# Вывести описание без чтения credentials, файлов записи и запуска браузера.
node scripts/demo/record.mjs --help
```

Настроить `RYADOM_DEMO_URL`, `RYADOM_DEMO_USERNAME`, `RYADOM_DEMO_SHA` локально для выбранного кандидата. Значения не включать в публичные инструкции и видеокадр. Для интерактивного ввода пароля в zsh:

```zsh
# Скрыто прочитать пароль синтетического аккаунта, не добавляя его в историю shell.
read -rs 'RYADOM_DEMO_PASSWORD?Пароль синтетического аккаунта: '

# Передать пароль дочернему процессу без вывода значения.
export RYADOM_DEMO_PASSWORD

# Записать реальный UI-проход. Эта команда импортирует источник и может подтвердить одно действие.
node scripts/demo/record.mjs

# Удалить пароль из environment текущего shell после завершения.
unset RYADOM_DEMO_PASSWORD
```

Сценарий изменяет состояние только через обычные UI-действия. Успешный импорт или confirm может уже сохраниться до последующей ошибки сети, UI или видео. Скрипт не откатывает изменения. После `FAILED` сначала проверить metadata и состояние синтетической цели. Не удалять память ради повторного «первого» прохода. Повтор постоянного текста должен показать duplicate.

## Файлы и статусы

Каждый запуск создаёт отдельный `run-<случайный суффикс>/`. После закрытия контекста:

- `completed-text/demo.webm` — проверенный новый текстовый импорт с одним confirm.
- `duplicate-text/demo.webm` — честный повтор сохранённого источника без confirm.
- `failed/demo.webm` — видеозапись незавершённого/ошибочного прохода, если браузер успел её сохранить.
- `metadata.json` — фактические начало/конец, timestamp шагов, SHA с пометкой происхождения, статус, body hash, факт duplicate и подтверждения, путь к видео и безопасный код ошибки. Полные ответы API, пароль, username, URL, cookies и storage state не сохраняются.

`confirmationAttempted: true` и `confirmationPerformed: null` означают, что попытка была, но наблюдений недостаточно для достоверного результата. Если подтверждение проверено, а обновление прогресса затем не удалось, `confirmationPerformed: true` остаётся в записи с общим статусом `FAILED`. При аварийном завершении процесса, принудительном kill или сбое записи файла metadata/video могут не финализироваться. Наличие временных файлов `pending/` не является успешным результатом.

Playwright записывает сам экран, включая поле username и **маскированное** поле password. Поэтому аккаунт должен быть исключительно синтетическим. Не сохраняются trace, HAR, логи консоли, auth headers и storage state. Приложение обязано само не показывать секреты. Весь ролик нужно посмотреть вручную до передачи или публикации. Автоматической внешней публикации нет. Не коммитить большой WebM в Git без решения владельца.

## Ручной вариант и аудио

Если селекторы изменились или нужен показ с объяснением, использовать ручной workflow из [REHEARSAL.md](REHEARSAL.md) и [DEMO_SCRIPT.md](DEMO_SCRIPT.md): обычный вход, подготовленная цель, текст, исходная цитата, confirm, повтор и пересмотр. Записать настоящий экран штатным средством машины. На подписи указать фактические SHA, время и режим. Не заменять результат модели fixture и не выдавать сохранённый проход за текущий live-вызов.

Короткое аудио на принятом eba453c прошло реальный STT и UI-проверки C. Для его записи вручную загрузить синтетический файл, дождаться настоящей расшифровки, открыть цитату и отдельно решить, можно ли подтвердить действие. При смене среды сначала повторить её проверку. Не автоподтверждать неизвестное событие и не добавлять выдуманные таймкоды. Text-harness сам по себе не доказывает готовность аудио, restart, публичного HTTPS/iPhone или двух человеческих репетиций.
