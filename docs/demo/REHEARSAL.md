# Репетиции и резервная запись

Состояние на 25 октября 2026: основной MVP принят интегратором, существуют две реальные короткие текстовые записи. **Обе человеческие репетиции, полный трёхминутный ролик text+audio и физический проектор пока NOT_RUN.** Новый публичный HTTPS/TLS-проход на iPhone находится в работе, физический iPhone NOT_RUN. Эти пункты не становятся выполненными по наличию слайдов, автотестов или короткого WebM.

## До репетиций

- [ ] Зафиксировать один кандидат: SHA, машина, время МСК, режим (полный или сокращённый текстовый).
- [ ] Сверить актуальную приёмку A по [MVP_ACCEPTANCE.md](../agents/MVP_ACCEPTANCE.md). Live text, live STT, reload/restart, упаковка и узкий экран имеют самостоятельные результаты PASS/FAIL/NOT_RUN.
- [ ] Проверить обычный вход и новую демонстрационную цель с пустым прогрессом. Не очищать личную память или чужую среду.
- [ ] Принять синтетический корпус B в `docs/demo/sources/`. Проверить содержание короткого аудио, отсутствие личных данных и его происхождение.
- [ ] Сверить среду показа с принятым eba453c: реальный STT уже прошёл семь чистых UI-проверок C. Короткое text-only видео называть текстовым резервом, а не записью полного аудиосценария.
- [ ] Открыть [defense/index.html](defense/index.html) локально. Проверить экран проектора, читаемость с последнего ряда, стрелки, пробел, `1`–`4`, `F`, `N` и видимый фокус при Tab.
- [ ] Открыть рабочий UI отдельно. Скрыть environment, ключи, адресную строку с access-bearing URL, уведомления и посторонние вкладки. Не включать приватные записи в демонстрацию.
- [ ] Заморозить функции в 15:45 МСК. После freeze менять только блокирующие дефекты, затем повторять затронутые проверки на новом SHA.

## Репетиция 1 — человеческий сквозной проход

Плановый слот: 16:15–16:45 МСК. Один человек выступает, другой следит за временем и проверяет понятность. Автоматическая проверка HTML репетицией не считается.

- [ ] Пройти [DEMO_SCRIPT.md](DEMO_SCRIPT.md) целиком с четырьмя экранами и реальным UI.
- [ ] Засечь общее время и длительность живых запросов. Цель — 3:00 вместе с переключениями. При превышении сократить речь или действия, не заявлять неподтверждённое время отклика.
- [ ] Убедиться, что зритель различает намерение, предложение модели и подтверждённое действие.
- [ ] Показать точную цитату, изменение прогресса и отсутствие роста при повторе. Проверить пересмотр подтверждения.
- [ ] Для полного сценария пройти настоящий STT и тот же evidence pipeline. Если он не прошёл, записать FAIL и выбрать честную резервную речь.
- [ ] Потренировать задержку запроса и переход к существующему резерву без выдуманного успеха.
- [ ] Записать замечания и исправить только необходимые проблемы. Отдельно указать новый SHA, если код изменился.

## Резервное видео — запись настоящего прохода

Короткие реальные текстовые записи созданы: [dev ef360ae](defense/recordings/text-ef360ae/completed-text/demo.webm), 15,04 с, и основной [production eba453c](defense/recordings/production-eba453c/completed-text/demo.webm), 16,12 с. Обе 1440×900, `COMPLETED_TEXT`, новый источник, точная цитата, confirm и server mock 0→1. [Metadata и границы записей](RECORDING.md). Они не содержат полного трёхминутного рассказа и аудиопути. Ниже workflow и shot list для оставшегося полного ролика. Не генерировать успешные результаты и не монтировать fixture как живой ответ модели.

1. После успешного прохода открыть новую синтетическую demo-цель на том же кандидате. Записать SHA и дату, проверить отключённые уведомления. Использовать штатную запись экрана выбранной машины, без установки нового сервиса.
2. Снять один непрерывный проход рабочего UI. Паузы модели сохранить или явно пометить сокращение ожидания. Закадровую речь можно записать отдельно, но она должна соответствовать видимым действиям.
3. Начать с подписи: «Запись реального прохода. Синтетические данные. SHA: <фактический>, дата/время: <фактические>, режим: <полный / текстовый резерв>». Это шаблон подписи, не готовые метаданные.
4. Не снимать секреты и личные записи. Если они попали в кадр, перезаписать фрагмент до передачи. Не выкладывать наружу и не добавлять большой бинарный файл в Git без отдельного решения владельца.
5. Сохранить локально в `docs/demo/defense/recordings/` с понятным именем и передать путь владельцу. Посмотреть итоговый файл целиком с аудио, проверить воспроизведение без сети и перемотку. Отметить запись ниже только после просмотра.

| Кадр | Что видно | Что доказывает запись |
|---|---|---|
| 1 | Подпись, цель и три пустых критерия | Какой кандидат и синтетический сценарий показаны |
| 2 | Импорт намерения и результат обработки | Намерение не увеличивает прогресс |
| 3 | Импорт действия, исходная цитата, подтверждение | Связь источника, решения человека и прогресса |
| 4 | Повтор того же источника | Счётчик остаётся прежним |
| 5 | Отклонение подтверждённой записи | Сервер пересчитывает прогресс |
| 6, только полный режим | Загрузка синтетического аудио, настоящая расшифровка, цитата, confirm | Реальный STT и единый путь review |
| 7 | Reload и сохранённое состояние | Что именно видно после перезагрузки страницы. Это не доказательство restart сервера |
