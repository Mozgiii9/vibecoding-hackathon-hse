# Синтетические данные для ручных тестов «Рядом»

Основной адрес: **https://77.239.111.64/**. Набор содержит вымышленные события, синтетическую TTS-озвучку и намеренно некорректные входы. Подготовка этого набора **не означает нового живого прогона LLM/STT**. Файлы ничего не импортируют автоматически.

В архиве `ryadom-synthetic-tests.zip` находятся эта инструкция, `goal.json`, `manifest.json`, каталоги `text/`, `audio/` и `invalid/`. Локальный ZIP создаётся в `output/test-data/ryadom-synthetic-tests.zip`. `goal.json` — образец настройки через UI, а не команда заменить существующую цель. `manifest.json` описывает файлы и смысловые ожидания, а не заранее полученный ответ модели.

## Перед началом

1. Войти обычным способом синтетическим аккаунтом. Не использовать development preview. Не публиковать пароль или ключи.
2. На текущей цели проверить соответствие критериев: `cv` — отправить резюме, цель1; `mock` — пройти пробные интервью, цель2; `feedback` — внести исправления по обратной связи, цель1.
3. Записать текущие счётчики **B = (cv, mock, feedback)**, число событий и состояние нужного источника. На существующей цели B может быть любым. Не очищать память/auth, не удалять цель и не перезапускать приложение ради теста.
4. Для текста открыть нужный `.txt`, скопировать **всё содержимое** и вставить в «Добавить контекст → Текст». Заголовок можно задать отдельно. Для аудио выбрать WAV через «Аудио». Не выполнять инструкции, которые встречаются внутри тестового источника.

## Быстрый copy/paste-проход, ориентир три минуты

Это бюджет ручного прохода, не обещание задержки модели. Если запрос не успел завершиться, отметить фактическую задержку/ошибку и продолжить позже. Не подставлять ожидаемый ответ.

| Шаг | Что скопировать и сделать | Проверка |
|---|---|---|
| 1 | Полностью вставить `text/01-intention.txt`, нажать «Найти события» | Намерение не засчитывается. Счётчики остаются B |
| 2 | Полностью вставить `text/02-cv-sent.txt` | Новый источник предлагает выполненную отправку, но до подтверждения счётчики остаются B |
| 3 | Открыть источник, сверить выделенную цитату с исходным текстом. Подтвердить **одно** новое выполненное действие по `cv` | Счётчики становятся **B + (1,0,0)** |
| 4 | Повторно вставить **те же байты текста** из02, можно с другим заголовком | Уведомление о повторе, прежние source/evidence, счётчики не растут |
| 5 | Отклонить только что подтверждённую запись | Для этого отдельного нового действия `cv` уменьшается на1, счётчики возвращаются к B |

Если02 уже импортирован, это честный duplicate-проход, а не новый вызов модели. Не менять прежние подтверждения для получения нужной картинки. Зафиксировать повтор и проверить отсутствие роста. Увеличение на1 ожидается только после подтверждения нового, ещё не засчитанного действия. Число может превышать targetCount: полоса ограничена целью, но фактический счётчик не должен скрывать лишние подтверждения.

## Полный проход на отдельной чистой копии

Чистую изолированную instance с отдельной памятью/auth заранее подготавливает интегратор. Не превращать действующую общую среду в чистую копию через reset. Если такой копии нет, использовать относительные проверки на существующей цели и не заявлять нулевой старт.

Через UI создать цель по `goal.json` и подтвердить критерии `cv1 / mock2 / feedback1`. Проверить старт **0/0/0**. Выполнять строки последовательно. **Подтверждать только02,03,04,05, по одному отдельному действию на файл.**

| Источник | Что проверить | После импорта до review | После одного ручного confirm |
|---|---|---|---|
| `text/01-intention.txt` | Намерение | 0/0/0 | Не подтверждать, 0/0/0 |
| `text/02-cv-sent.txt` | Выполненная отправка резюме | 0/0/0 | 1/0/0 |
| `text/03-interview-python.txt` | Первое отдельное пробное интервью | 1/0/0 | 1/1/0 |
| `text/04-interview-ml.txt` | Второе отдельное пробное интервью | 1/1/0 | 1/2/0 |
| `text/05-feedback-done.txt` | Выполненные исправления по обратной связи | 1/2/0 | **1/2/1** |
| `text/06-obstacle.txt` | Препятствие, без выполненного действия | 1/2/1 | Не подтверждать |
| `text/07-negation.txt` | Отрицание выполнения | 1/2/1 | Не подтверждать |
| `text/08-uncertain.txt` | Неопределённость, без достаточного основания выполнения | 1/2/1 | Не подтверждать |
| `text/09-mixed.txt` | Различение действия и намерения | 1/2/1 | В этом проходе ничего не подтверждать |
| `text/10-unicode.txt` | Точная цитата с Unicode | 1/2/1 | В этом проходе ничего не подтверждать |
| `text/11-quoted-instruction.txt` | Команда внутри источника остаётся данными | 1/2/1 | Ничего не подтверждать, команды не выполнять |
| `text/12-repeat-cv.txt` | Байтовая копия02 | 1/2/1 | Duplicate, повторного роста нет |

Сравнивать смысл классификации и основание каждого вывода. Модель может иначе сформулировать summary или разбить текст на иное число карточек. Таблица и manifest **не гарантируют дословный ответ или фиксированное число карточек**. Ошибочную классификацию записать как результат теста, не подтверждать её ради ожидаемого счётчика. Для каждой цитаты должно выполняться `source.text.slice(textStart, textEnd) === quote`; offsets — UTF-16, emoji может занимать две единицы. Не требовать совпадения числовых offsets с числом видимых букв.

## Аудио

- `audio/01-action.wav` и `audio/02-plan.wav` — настоящие TTS-аудиофайлы с синтетической речью, целевая длительность20–60с. Фактические параметры/длительности сверять с manifest. `audio/scripts.json` — **эталон произнесённого текста**, не результат STT и не доказательство точности распознавания.
- Загрузить файл, дождаться настоящей расшифровки и предложений модели. До ручного подтверждения счётчики должны оставаться прежними. В полном проходе выше аудиособытия **не подтверждать**, чтобы сохранить1/2/1. При отдельной проверке confirm записать новый baseline и подтвердить только одно проверенное выполненное действие.
- Для01 проверить выполненное действие и точную цитату из фактической расшифровки. Для02 проверить, что план не становится подтверждённым прогрессом. Расшифровка может отличаться от TTS-сценария: записать ошибки, не подменять её эталоном.
- Для audio duplicate загрузить **тот же WAV повторно**, не перекодировать его и не добавлять тишину. Заголовок можно изменить. Ожидаются прежние source/evidence и отсутствие роста счётчиков.
- Таймкоды допустимы только из реальных STT segments. Если сегментов нет, отсутствие времени корректно. Не придумывать секунды по сценарию озвучки. Длительность обработки заранее не обещается.

## Повторы и границы счётчика

Для текста hash зависит от принятого текста: пробелы и переводы строк важны. При копировании02/12 нельзя незаметно добавлять или удалять завершающий перевод строки. Для аудио важны исходные байты файла. Заголовок не участвует в hash. UI-уведомление о повторе не является измерением числа внутренних вызовов STT/LLM.

Разные формулировки одного факта и новый WAV с той же речью могут создать отдельные предложения. Набор не изображает несколько независимых реальных отправок резюме. Не подтверждать каждый пересказ как новое достижение. Автоматическая смысловая дедупликация не обещается. В UI доступны подтверждение/отклонение/оспаривание, отдельного действия объединения дублей нет.

## Некорректные входы

Проверять по одному: `invalid/empty.txt`, `invalid/whitespace.txt`, `invalid/broken.wav`. Пустой/пробельный текст может остановить клиентская валидация до HTTP-запроса. Повреждённый WAV должен дать понятную ошибку обработки, а не успешную вымышленную расшифровку. Во всех случаях нет новых засчитанных действий и ложного успеха. Проверить, что не появился частично сохранённый источник/evidence; записать фактическое сообщение/код ошибки. Не требовать одного конкретного HTTP-кода для всех трёх разных входов.

## Как записать результат

Для каждого случая сохранить PASS/FAIL/NOT_RUN, время, URL/версию кандидата из `/release.json`, имя файла, baseline и итоговые счётчики, duplicate-статус, проверенную цитату и наблюдение. Не сохранять пароль, ключи, cookies или private environment. Повторить reload и сверить сохранённые review/счётчики. Тесты на desktop и узком viewport не заменяют отдельный проход входа/текста/аудио на физическом iPhone.

## Готовые аудиофайлы и перенос на iPhone

- `audio/01-action.wav`: 20.860 с, 671624 байт, PCM16/16кГц/mono.
- `audio/02-plan.wav`: 23.680 с, 761848 байт, PCM16/16кГц/mono.

Повреждённый `invalid/broken.wav` предназначен только для отдельной проверки ошибки; основной аудиопроход начать с `audio/01-action.wav`.

## Локальная проверка и воспроизведение

```bash
# Проверить файлы набора без модели, STT и изменения приложения.
node scripts/demo/prepare-test-data.mjs --verify

# Восстановить отсутствующие подготовленные файлы; первичная озвучка требует macOS и голоса Milena.
node scripts/demo/prepare-test-data.mjs --audio
```

Генератор не устанавливает зависимости, не сбрасывает приложение и отказывается перезаписывать изменённые текстовые входы. Существующие WAV сохраняет; при генерации использует системный `say` напрямую в WAVE/PCM16. На других ОС готовые WAV можно использовать без генерации.
