# Чат по личному контексту

**Публично развёрнут 25 октября 2026, 16:50 МСК:** [версия и проверка сайта](CONTEXT_CHAT_DEPLOYMENT.md). Исходный отчёт реализации ниже сохранён как история приёмки.

Раздел `/chat` открывается кнопкой «Чат с агентом» на странице цели. Переписка относится к текущей цели и сохраняется на сервере. Несохранённый текст остаётся при переходе к цели и обратно; при выходе из аккаунта очищается.

## Откуда берутся ответы

Чат читает цель, её критерии, текущий подтверждённый прогресс, все сохранённые текстовые источники и аудиорасшифровки этой цели. Заметки без выделенных событий тоже доступны. Он не обходит произвольные файлы памяти, не получает vault/env, не использует общий agent loop, инструменты или поиск в интернете.

Модель выбирает релевантные дословные цитаты из переданных материалов. Сервер проверяет ID источника, точное вхождение, границы и неоднозначность цитаты. В ответ попадают только проверенные цитаты и фиксированная вводная фраза. Произвольный текст ответа модели, выдуманные сведения и ссылки не принимаются. Цитата расширяется до полного предложения, чтобы не терять отрицания. Аудиотаймкоды вычисляются по реальным сегментам расшифровки.

Если в материалах нет ответа, агент сообщает об этом. История диалога помогает понять уточняющий вопрос, но не становится новым источником фактов. Чтобы добавить сведения в контекст, нужно сохранить заметку или расшифровку через страницу цели.

Такой режим намеренно даёт ответы с основаниями, а не свободные рассуждения из общих знаний модели. Запись в заметке сама по себе не доказывает выполненное действие; подтверждённый прогресс вычисляется из актуальных статусов событий на сервере.

## API и хранение

- `GET /goals/:goalId/chat` — история и краткая информация о доступном контексте.
- `POST /goals/:goalId/chat` — `{ "message": "…", "requestId": "UUID" }`, до 4000 символов. Возвращает историю, проверенный ответ и его источники.
- Обе операции требуют штатной авторизации и `memory_access`. Actor и memory root берутся с сервера. Клиент не выбирает пользователя, путь к памяти или документы.
- История изолирована по memory root, actor и цели, хранится в `hackathon/context-chat`. Пара вопрос/ответ записывается атомарно; повтор того же requestId не создаёт второй ответ. Ошибка модели не превращается в сохранённый успешный ответ.
- Новый API не меняет контракты импорта/целей и не отправляет вопросы в unrestricted `/message`.

Ключ модели остаётся в серверных `HACKATHON_LLM_*` настройках. Для чата используется тот же OpenAI-compatible Gemini transport, что и для обработки контекста; автоматического fallback нет.

### Повторить браузерную проверку

Нужна **свежая изолированная синтетическая среда**: runner создаёт owner и цель, поэтому его нельзя запускать на существующей пользовательской памяти. Existing `scripts/release/browser-runtime.mjs` может запустить временные gateway/Vite без MCP. Использовать свой private env с `HACKATHON_LLM_*`, не ключ в CLI. Пример с локальным файлом:

```sh
RELEASE_MODE=live RELEASE_GATEWAY_PORT=8895 RELEASE_WEB_PORT=5129 \
HACKATHON_LLM_TIMEOUT_MS=120000 \
node --env-file=PRIVATE_ENV scripts/release/browser-runtime.mjs
```

В другом shell:

```sh
CONTEXT_CHAT_ALLOW_SYNTHETIC=1 CONTEXT_CHAT_URL=http://127.0.0.1:5129 \
CONTEXT_CHAT_OUTPUT=/private/tmp/ryadom-context-chat-check \
node scripts/context-chat/check-browser.mjs
```

После проверки остановить только этот локальный runtime. Его память временная, предназначена исключительно для тестовых данных; постоянный пользовательский запуск использует штатный source launcher и отдельный постоянный INSTANCE. Скриншоты делаются после синтетической авторизации; trace/HAR/video/auth headers не сохраняются.
