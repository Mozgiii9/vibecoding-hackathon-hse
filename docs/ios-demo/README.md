# «Рядом»: установка iOS demo через Xcode

Это SwiftUI-оболочка с `WKWebView`, которая открывает настоящий HTTPS web UI «Рядом». Авторизация, цели, обработка текста и аудио работают через общий web UI и сервер; установка оболочки сама по себе не подтверждает готовность этих сервисов.

Проект: `clients/ios-demo/RyadomDemo.xcodeproj`, схема: `RyadomDemo`, минимальная версия iOS: **16.0**. Сторонних зависимостей нет. Для личной установки с Mac на свой iPhone достаточно Apple Account и **Personal Team** в Xcode; платная программа Apple Developer, App Store и TestFlight для этого сценария не нужны.

## Что подготовить

- Mac с Xcode и поддержкой версии iOS подключаемого iPhone. В среде подготовки найдены Xcode 27 и iOS SDK 27. Подтверждены установка и запуск оболочки на физическом iPhone Air с iOS 27.0.1; настоящий UI пока не загрузился из-за недоступности сервера.
- Разблокированный iPhone с iOS 16.0 или новее и кабель для первого подключения.
- Apple Account, добавленный в Xcode → Settings → Accounts.
- Рабочий HTTPS-адрес **самого web UI**, доступный с iPhone. Его сертификат должен проходить обычную проверку iOS. `localhost` на iPhone указывает на телефон, а не на Mac.
- Обычную тестовую учётную запись сервиса и синтетические данные. Ключи модели и STT находятся на сервере; не помещать их в URL, конфигурацию клиента или Git.

Владелец указал кандидат `https://77.239.111.64/`, однако рабочий TLS endpoint ещё не подтверждён. Порты и настройка HTTPS — зависимость от интегратора; подготовлен [вариант с IP-сертификатом](HTTPS_IP.md). Таблица приёмки находится в [DEMO.md](DEMO.md).

## Указать HTTPS-адрес

1. В корне репозитория создать локальный файл с одной настройкой. `App.xcconfig` уже подключает `Local.xcconfig`; копировать его целиком нельзя, иначе получится рекурсивное подключение:

   ```bash
   # Создать локальную конфигурацию, не перезаписывая существующую.
   if [ ! -e clients/ios-demo/Config/Local.xcconfig ]; then
     cat > clients/ios-demo/Config/Local.xcconfig <<'EOF'
   RYADOM_APP_URL = https:/$()/demo.example.invalid/app/
   EOF
   fi
   ```

2. В `clients/ios-demo/Config/Local.xcconfig` задать свой адрес в параметре `RYADOM_APP_URL`:

   ```xcconfig
   RYADOM_APP_URL = https:/$()/demo.example.invalid/app/
   ```

   `demo.example.invalid` — заглушка, её нужно заменить подтверждённым хостом; `/app/` — пример пути, используйте настоящий путь web UI. В `.xcconfig` последовательность `//` начинает комментарий, поэтому запись `https://…` может обрезать значение. Пустая подстановка `$()` в `https:/$()/…` позволяет получить `https://…` после обработки Xcode. Не переносить эту специальную запись в Safari: в браузере нужен обычный `https://…`.

3. Сохранить файл и пересобрать приложение. Изменение `.xcconfig` не меняет уже установленную сборку. `Local.xcconfig` исключён из Git; он не предназначен для секретов. В URL не должно быть логина, пароля, API-ключа или токена входа.

Использовать адрес живого UI, а не API, дизайн-превью или локального fixture. Допустим домен или публичный IP, если HTTPS-сертификат действителен именно для указанного адреса и доверен iOS. Самоподписанный сертификат и HTTP не подходят для этого demo; не отключать проверку TLS или защиту транспорта ради запуска. До сборки вручную открыть обычный HTTPS-адрес в Safari на iPhone и убедиться, что он доступен без предупреждения о сертификате.

## Подписать и запустить на своём iPhone

1. Открыть `clients/ios-demo/RyadomDemo.xcodeproj` в Xcode. Выбрать схему **RyadomDemo**.
2. Открыть target **RyadomDemo** → **Signing & Capabilities**. Включить **Automatically manage signing** и выбрать свой **Personal Team**.
3. Проверить **Bundle Identifier**: `ru.mozgiii9.ryadom.iosdemo`. Если Xcode сообщает, что идентификатор недоступен для выбранной команды, задать уникальный идентификатор своей команды и записать его в протокол приёмки. Изменение bundle id создаёт отдельное приложение; сохранённая сессия прежней установки туда не переносится.
4. Подключить разблокированный iPhone. Подтвердить **Trust / Доверять** при запросе на телефоне и разрешить сопряжение с Mac. Выбрать этот физический iPhone как Run Destination в Xcode; дождаться подготовки устройства.
5. Если Xcode просит **Developer Mode**, включить его на iPhone: **Настройки → Конфиденциальность и безопасность → Режим разработчика**. Выполнить предложенную перезагрузку и подтвердить включение после неё. Пункт может появиться после первого сопряжения/попытки запуска из Xcode.
6. Нажать **Run** в Xcode. Разрешить Xcode штатно создать сертификат и профиль для выбранной команды. При запросе доступа к ключу подписи разрешать его только ожидаемому Xcode.
7. Если iOS блокирует запуск как недоверенного разработчика, открыть **Настройки → Основные → VPN и управление устройством**, выбрать запись своего Apple Account/Developer App и подтвердить доверие. Если такой записи нет, этот шаг не требуется; следовать фактической подсказке iOS.
8. После успешного запуска остановить запуск из Xcode и открыть **«Рядом» с иконки на iPhone**. Выполнить все восемь пунктов [физической приёмки](DEMO.md#физическая-приёмка-восемь-пунктов).

Personal Team предназначен для личной разработки и имеет ограничения бесплатного provisioning. Подпись не бессрочна: при сообщении об истёкшем профиле снова подключить iPhone и запустить актуальную сборку из Xcode. Это не пакет для публичной установки или распространения через TestFlight.

Для текущего устройства Personal Team и профиль выбраны через Xcode, Developer Mode включён, пользователь подтвердил доверие Developer App на iPhone. Оболочка установлена и открывается с иконки. Личный `DEVELOPMENT_TEAM` перенесён в ignored `Local.xcconfig`. При выборе команды Xcode может добавить её ID в `project.pbxproj`; перед публикацией перенесите настройку в локальный конфиг и удалите только соответствующие переопределения target. Сертификат, private key и provisioning profile в Git не добавляются.

## Проверка исходников без подписи

```bash
# Проверить URL/navigation policy и синтаксис plist/project без установки на устройство.
clients/ios-demo/scripts/check.sh
# Собрать arm64 приложение без подписи; результат не устанавливается на iPhone.
xcodebuild -project clients/ios-demo/RyadomDemo.xcodeproj \
  -scheme RyadomDemo -configuration Debug -destination 'generic/platform=iOS' \
  -derivedDataPath clients/ios-demo/build/DerivedData CODE_SIGNING_ALLOWED=NO build
```

В изолированном agent sandbox штатный SwiftUI compiler plugin Xcode может завершаться с `sandbox_apply: Operation not permitted`; сборка из обычного Xcode/Terminal проходит. Не отключать macOS protections и не менять исходники ради такого ограничения среды. Логи и DerivedData в `clients/ios-demo/build` исключены из Git.

## Вход, сессия и аудио

Войти через обычную форму сервиса в приложении. Сессии Safari и `WKWebView` могут быть отдельными: вход в Safari не доказывает вход в оболочке. Закрытие и повторное открытие проверяются на том же устройстве и той же установленной сборке; удаление приложения, выход из аккаунта или истечение серверной сессии меняют условия проверки.

Для аудио выбрать в web UI **«Аудио» → «Аудиофайл»**, затем файл из приложения «Файлы» и **«Найти события»**. Для demo подготовить синтетическую запись 20–60 секунд в **M4A, WAV или MP3**, не пустую, размером **не более 10 MiB (10 485 760 байт)**. Файл должен быть доступен локально на телефоне; при хранении в облаке дождаться его загрузки. Сервер и UI проверяют MIME-тип: переименование расширения не преобразует формат. Если файл отклонён, записать ошибку и проверить корректный экспорт, не обходить валидацию.

Общий UI сейчас использует выбор готового аудиофайла; отдельной записи с микрофона нет. Доступ к микрофону не является условием этого demo. Успех аудиопункта требует реально настроенного серверного STT, полученной расшифровки и прохождения evidence-сценария. Ошибка `stt_unconfigured` означает незакрытый аудиопункт, а не успешную обработку. Таймкоды показывать только при наличии настоящих данных STT.

## Если установка или сеть не готовы

| Симптом | Действие |
|---|---|
| Xcode не видит iPhone | Проверить кабель, разблокировку, доверие к Mac и совместимость Xcode с iOS; выбрать физическое устройство в Run Destination. |
| Ошибка signing/provisioning | Проверить Apple Account, Personal Team, автоматическую подпись и уникальный bundle id. Читать конкретную ошибку Xcode. |
| Ошибка URL или пустой экран | Проверить `Local.xcconfig`, формат `https:/$()/…`, настоящий путь UI и пересобрать. Проверить тот же адрес в Safari на телефоне. После восстановления сети нажать «Повторить загрузку», если показан экран ошибки оболочки. |
| Сертификат недоверенный | Исправить HTTPS endpoint; не обходить TLS-проверку. |
| UI открыт, но вход/импорт не работает | Проверить обычный вход и доступность общего API у владельца web-среды. Доступность HTML не доказывает доступность backend или модели. |
| Сессия потерялась после открытия | Зафиксировать устройство, iOS, сборку и действия; проверить вход заново. Пункт 7 остаётся FAIL до исправления или объяснения серверного истечения сессии. |
| Аудио вернуло ошибку | Записать формат, размер и код ошибки без содержимого частной записи. Проверить STT с владельцем общего сервиса. |

Резерв: открыть тот же настоящий HTTPS-адрес в Safari на iPhone. При желании выбрать **Поделиться → На экран «Домой» / Add to Home Screen**. Это **веб-версия с ярлыком**, а не нативная установка и не доказательство приёмки `RyadomDemo`. Safari использует собственную сессию; войти отдельно. Если резерв используется на показе, назвать его веб-версией и оставить непройденные пункты iOS-оболочки открытыми.

Если оболочка предлагает открыть внешнюю ссылку, проверить адрес в подтверждении и выбрать **«Открыть»** или **«Отмена»**. Выход во внешний браузер не является продолжением сессии внутри `WKWebView`.

## Граница готовности

Сборка симулятора, успешная компиляция и наличие иконки не заменяют сквозной запуск на физическом iPhone. Результат фиксировать по [DEMO.md](DEMO.md): устройство, iOS, SHA оболочки и web-кандидата, версия Xcode и статусы PASS/FAIL/NOT_RUN. Не публиковать credentials, приватные endpoint с доступом, записи или содержимое сессии.
