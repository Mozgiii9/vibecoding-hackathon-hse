# Готовые цели для второй итерации

**Это черновики для передачи участникам, цели ещё не запущены.** Вставить нужный блок целиком в чат соответствующего Codex после решения владельца начать разработку. /goal задаёт результат конкретного чата; файл сам по себе не создаёт цель у участников.

Официальный [Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex) описывает синтаксис /goal с результатом и проверяемым завершением. Поддержку команды проверить в клиенте участника. Здесь нет специальных флагов дедлайна, модели или токенов: ограничения записаны обычным текстом. Новые сабагенты — GPT‑6.1‑Sol/high.

## Участник A

~~~text
/goal Подготовь проверенный выпуск нашего «Рядом» для защиты 25 октября 2026 к 17:15 МСК: воспроизводимый запуск именно нашего кода, браузерная приёмка основного сценария, сохранность состояния и короткая инструкция восстановления. Жёсткий дедлайн команды 17:30, новые функции прекращаем в 15:45.

Репозиторий Mozgiii9/vibecoding-hackathon-hse. Прочитай AGENTS.md, docs/agents/ITERATION_2.md и docs/agents/AGENT_A_RELEASE.md. Начинай от актуального origin/codex/integration-ui с этим планированием и кодом 35b093b в истории, работай в новой ветке codex/qa-release. Старые ветки не переписывай. Перед переключением проверь рабочее дерево; собственные изменения сохрани обычным проверенным коммитом, чужие не трогай.

Очередь A1→A2→A3→A4: приёмка, source-build нашего форка, restart/backup/runbook, независимая проверка кандидата. Не жди чужой UI или ключ, если можно проверить запуск/auth/сохранность. Блокировка дольше 5 минут: запиши причину в docs/status/agent-a.md и сразу возьми независимую задачу своей очереди. Не заканчивай после первого результата, пока есть доступная работа в этой границе.

Можно до двух сабагентов GPT-6.1-Sol/high в непересекающихся файлах. Не меняй чужие модули, gateway, общий API или manifests без передачи владельцем. Никакого Stitch. Секреты и runtime-данные в Git не помещай. Подготовка пакета не разрешает серверный deployment: нужно отдельное указание владельца на целевое окружение.

Передавай небольшие проверенные коммиты и push только своей ветки, первый результат за 20–30 минут. В status указывай base SHA, ready SHA, проверки, blocker и следующую задачу. Интеграцию в общую ветку делает C.

Завершение подтверждают docs/release/ACCEPTANCE.md, RUNBOOK.md и KNOWN_ISSUES.md: проверенный наш source-build, запуск, auth, импорт/цитата/confirm/duplicate/reject и restart на конкретном кандидате. Разделяй PASS/FAIL/NOT_RUN и тестовый provider/реальный LLM. Если доступные пути исчерпаны, передай частичный результат, доказательства и точный ресурс для продолжения. Не объявляй непроверенное готовым или цель достигнутой только из-за времени.
~~~

## Участник B

~~~text
/goal Доведи вход жизненного контекста в «Рядом» до проверяемого demo: надёжный текстовый extraction через наш Gemini и короткое аудио через один реально работающий STT, если он доступен в установленный cutoff. Передай проверенный корпус и ограничения к 15:15 МСК 25 октября 2026. В 15:45 прекращаем новые функции; проект готовим к 17:15, жёсткий дедлайн 17:30.

Репозиторий Mozgiii9/vibecoding-hackathon-hse. Прочитай AGENTS.md, docs/agents/ITERATION_2.md и docs/agents/AGENT_B_AUDIO_QUALITY.md. Начинай от актуального origin/codex/integration-ui с этим планированием и кодом 35b093b в истории, новая ветка codex/audio-quality. Старый текстовый pipeline уже объединён, не переписывай его.

Очередь B1→B2→B3→B4: за 10 минут проверь реально доступный STT; подключи один transcribe adapter; проверь 8–10 смысловых случаев extraction; подготовь 4–6 synthetic demo-источников и ожидаемые выводы. Нет рабочего STT за 10 минут — сразу делай качество и корпус, вернись к аудио только при конкретном ресурсе. Решение о включении аудио до 14:30. Разрешённый fallback — явно обозначенный text-only release с причиной отсутствия аудио, без обещания его работы.

Можно до двух сабагентов GPT-6.1-Sol/high: STT и качество/корпус в разных файлах. Соблюдай владение из ITERATION_2.md; gateway, UI, goals-core, shared API и manifests меняет C. Новый интерфейс или зависимость сначала предложи C, параллельно продолжай независимые задачи. Никакого Stitch, второго backend или БД. Если необходим минимальный Python STT-компонент — uv/.venv, Pydantic, docstrings и ruff/mypy; сначала доказать пригодность на целевой машине.

Не передавай ключи в Git, frontend или reports. Нет live key — проверяй parser/negative cases и корпус, реальные запросы помечай NOT_RUN. Не гадай о поддержке аудио у Gemini. Quote остаётся точным фрагментом, времена только из STT, намерение не подтверждается автоматически, ошибки не оставляют частичного источника.

Публикуй небольшие проверенные части, exports/config без ключей и status в docs/status/agent-b.md, первый результат за 20–30 минут. После части сразу следующая доступная задача, без ожидания «что дальше».

Завершение: результаты реального extraction на приёмочных примерах, воспроизводимый audio→transcript→evidence на целевой машине либо честный text-only handoff по принятому cutoff, demo-корпус и docs/handoffs/agent-b-wave2.md с SHA/проверками/ограничениями. Fixture не равен живому ответу. Если весь остаток заблокирован, передай доказательства и нужный ресурс. Не отмечай аудио готовым или всю цель успешной просто по истечении времени.
~~~

## Применение

Владелец отправляет только нужный блок в соответствующий чат. Если там уже есть незавершённая цель, сначала проверить её состояние и сознательно решить, как заменить или завершить её, не наслаивать поручения вслепую. Между задачами одной цели новый /goal не нужен.

Проверенные результаты означают завершение, отчёт о блокировке не подменяет успех. Продолжение зависит от установленного Codex и его ограничений; эти промпты не обещают бесконечную автономность и не создают расписание.
