Сначала кратко назови последовательность и приступай: разрешение на реализацию в этой границе передаётся владельцем вместе с заданием. Если пользователь явно просит только анализ, соблюдай этот предел. Не жди готовности UI или соседней ветки: используй порт и фикстуры в тестах.

## Файлы и результат

Ты единственный владелец `app/builds/typescript/features/goals/**` и `docs/handoffs/agent-a.md`. Создай `index.ts` с экспортами `createGoalsStore` и `registerGoalsRoutes` строго по API_V1.md. Раздели store, progress, routes и схемы по небольшим файлам. Базовая архитектура TypeScript/Fastify/Zod, existing Vitest. Новые БД, Python backend или собственная авторизация не нужны.

Не изменяй `features/contracts.ts`, `gateway/server.ts`, `features/context/`, web client, manifests и lockfiles. Gateway подключает интегратор; для самостоятельных проверок создай Fastify instance в своём тесте. Внутри модуля применяй существующую `authorize(request.authContext, "memory_access")`, ошибки доступа отображай корректно как 403, а не 500.

## Последовательность

1. **Первый коммит:** структуры модулей, экспорт портов, валидация GoalWrite и CRUD цели, сборка. Опубликуй ветку, чтобы интегратор видел экспорты.
2. **Хранилище:** один JSON snapshot под переданным memoryRoot, проверка schema при чтении; очередь mutations, atomic rename. Сбой записи не считается успехом. Никаких произвольных путей из пользовательского ID.
3. **Import port:** проверка подтверждённой цели, findImport, атомарный source+evidence. Повторный импорт не сбрасывает статусы. Перепроверь цитаты и criterionId даже после validation агента B. Защити гонки импорта/подтверждения.
4. **Review и прогресс:** optimistic revision, допустимые переходы, уникальные eventKey, ручное объединение дубля. Счётчики вычисляются из состояния, не редактируются клиентом. nextStep сначала детерминированный, помеченный kind=rule.
5. **HTTP routes:** все A endpoints по контракту, стабильные ошибки. Source отдаётся только через защищённый маршрут. Goal lock после первого импорта.
6. **Handoff:** экспортируемые функции, точный SHA, проверки и реальные ограничения. Push своей ветки; main и чужие ветки не изменять.

## Проверки, которые нужны

- intention нельзя подтвердить как действие; completed_action засчитывается только после confirmed.
- Один источник дважды/два параллельных импорта дают один набор ID; существующий rejected/confirmed сохраняется.
- Два подтверждённых evidence с одним eventKey считаются один раз внутри критерия.
- Отклонение/оспаривание уменьшает счётчик; неизвестный ID/устаревшая revision корректно отклоняются.
- source и evidence сохраняются вместе; ошибка записи не оставляет частично успешного состояния; reload сохраняет результат.
- Цитата не совпала/критерий отсутствует/цель изменилась → ошибка, никакого коммита источника.
- HTTP запрос без права memory_access не проходит. Большой `targetCount`, нули, дробные counts и дубли criterion ID валидируются.
