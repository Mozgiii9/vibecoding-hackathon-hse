# Совместная работа на тестовом сервере

Владелец разрешил агентам использовать тестовый сервер для необходимых проверок и изолированных тестовых запусков. Сервер: 77.239.111.64, SSH user root. Пароль передаётся отдельно владельцем в сообщении, в Git его нет. Сейчас обновлены только инструкции; это не запуск серверных работ из текущего чата.

## Первый вход

Сначала проверить существующие каталоги/процессы, занятые порты, Docker, CPU/RAM и место на диске. Не считать сервер пустым. Не читать чужие environment-файлы и не выводить секреты. В свой status записать только назначение среды, свой SHA, каталоги/порты и результаты.

Рабочий серверный workspace для этой задачи — только свой каталог внутри /srv/ryadom-hackathon/. Не работать из общего checkout и не менять его ветку. Существующие несвязанные приложения/каталоги сохранять.

## Назначения

| Владелец | Каталог | Compose project | Порты host, только loopback |
|---|---|---|---|
| A, release tests | /srv/ryadom-hackathon/agent-a | ryadom_a | UI 15073, gateway 18787 |
| B, context/audio | /srv/ryadom-hackathon/agent-b | ryadom_b | UI 16073, gateway 18788, STT 19000 |
| C, интегратор | /srv/ryadom-hackathon/integration | ryadom_c | UI 17073, gateway 18789 |

Это резервирование в плане, не утверждение, что порты свободны. Перед bind проверить каждый. Если порт занят — не останавливать процесс; выбрать свободный из своего диапазона (A 15073–15079 и 18787; B 16073–16079, 18788 и 19000–19009; C 17073–17079 и 18789), записать фактический адрес. При отсутствии свободного — сообщить C и продолжить независимую часть.

**Compose project name недостаточно.** Upstream Compose содержит явные общие volume names braindrive_memory / braindrive_secrets. В тестовом override назначить уникальные volumes для своего владельца либо bind mounts внутри собственного каталога. Не использовать общую пользовательскую память/секреты. Имена контейнеров/образов/сетей тоже уникальны, теги образов содержат владельца и SHA, не общий latest.

MCP 8911/8912/8913 могут совпадать внутри разных контейнерных сетей, но не на host. Их не публиковать. Dev runtime upstream жёстко использует эти порты: нельзя запускать три одинаковых npm run dev прямо на host. Для нескольких окружений использовать отдельные Compose networks либо заранее согласованный вариант с разными MCP портами.

## Общие ресурсы

Одновременно на сервере не более одной тяжёлой операции: сборка образа/массовая установка, загрузка/прогон STT или нагрузочный тест. Сначала измерить ресурсы; модель base/CPU или один worker не объявлять подходящими без проверки.

Для тяжёлой операции использовать общий advisory lock /srv/ryadom-hackathon/coord/heavy.lock через flock, если он доступен:

~~~bash
# Создать общий каталог координации, не затрагивая приложения.
mkdir -p /srv/ryadom-hackathon/coord
# Запустить свою тяжёлую команду только если ресурс свободен.
flock -n /srv/ryadom-hackathon/coord/heavy.lock <своя-команда>
~~~

Последняя строка — шаблон, заменить команду, не выполнять буквально. Если lock занят — перейти к лёгким тестам/корпусу/docs, не крутить цикл ожидания. Если flock отсутствует, не ставить пакеты глобально автоматически: согласовать временной слот с C. Lock-файл не удалять для обхода блокировки.

Каждый ведёт только свой файл /srv/ryadom-hackathon/coord/agent-a.md, agent-b.md или agent-c.md: кто, задача, SHA, PID/Compose project, порты, начало операции. Без паролей, токенов и environment dumps. Это координационные записи, не механизм авторизации.

## Общее приложение и тестовые данные

Общую integration-среду перезапускает/обновляет только C. A может проверять её без изменения данных либо по явно выделенному C окну/тестовой цели. Все create/import/reject/reset/restart тесты по умолчанию идут в собственной среде A/B с synthetic данными.

Не останавливать чужие контейнеры/процессы и не удалять чужие volumes. Не использовать глобальные docker system prune, docker volume prune, pkill node, reboot, глобальные обновления или изменения firewall/Docker daemon в рамках тестов. Останавливать только свои конкретные PID или свой Compose project. Общий root технически не разделяет права: эти ограничения должны соблюдать все агенты и их сабагенты.

Секреты допустимы только в private environment-файле своей среды с ограниченным доступом, не в tracked файлах, CLI arguments, отчётах/traces или публичных логах. Пароль не помещать в команду sshpass и shell history.

## Передача

В repo status/handoff записать свой SHA, способ запуска, адреса сервисов, фактически выполненные проверки и ограничения. Пароль не переносить. После себя остановить только собственные временные процессы, если они больше не нужны; общий кандидат C и полезный STT B сохранять до согласованной передачи.

Эта инструкция разрешает изолированные проверки на названном тестовом сервере. Общий публичный выпуск и переключение demo-кандидата остаются отдельной работой интегратора; агент A/B не делает их самостоятельно.
