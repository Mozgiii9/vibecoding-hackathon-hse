# Передача дизайна из Google Stitch

**Архив.** По последней инструкции пользователя Stitch больше не использовать. Дизайн делает C самостоятельно по [подтверждённому брифу](GOALS_BRIEF.md). Ниже историческая инструкция, не активное поручение.

Доступ к Stitch list_projects проверен, ответ получен. Генерация нового экрана и экспорт пока не проверены. Пользователь делает дизайн; текущий Codex интегрирует его в React. Backend агенты работают независимо от дизайна.

## Функциональный бриф для Stitch

Текст ниже можно вставить в новый проект Stitch. Это требования к содержимому, визуальное направление выбирает владелец.

> Спроектируй основной экран веб-приложения «Второй мозг» для человека, который готовится к ML-собеседованию. Весь интерфейс на русском. Пользователь согласует критерии цели, загружает выбранные заметки/переписку/короткое аудио, проверяет извлечённые события и видит подтверждённый прогресс.
>
> На экране: цель «Подготовиться к ML-собеседованию», срок 1 ноября; критерии «Отправить резюме: 1/1», «Провести пробные интервью: 1/2», «Внести правки по обратной связи: 0/1». Не показывай общий процент вероятности успеха.
>
> Нужны действия «Добавить текст», «Загрузить аудио», «Подтвердить», «Отклонить», «Посмотреть источник». Одно событие ещё ожидает подтверждения; другое — намерение «Завтра хочу отправить резюме», которое не увеличивает прогресс. Рядом с событием укажи его источник и статус. По выбору события раскрывается точная цитата и, если доступен, таймкод расшифровки.
>
> Покажи следующий шаг, связанный с незакрытым критерием. Включи состояние обработки и понятную ошибку с повтором. Не добавляй декоративные метрики, граф социальной сети, календарь, почту, фоновые микрофоны или функции, которых нет в этом сценарии. Для аудио MVP показывает расшифровку, плеер не обязателен.
>
> В первую очередь нужен один основной desktop экран, затем его узкая версия и состояние первого запуска с подтверждением критериев. Это рабочее приложение, а не рекламный лендинг. Визуальный стиль согласуй со мной отдельно.

## Что передать Codex

Ссылка или project ID нового проекта Stitch и название выбранного экрана. Codex сможет прочитать экран через connector и экспортировать HTML. Если доступен только файл экспорта, положить его в `docs/design/stitch/`. Для соответствующих действий нужны реальные состояния, а не несколько статичных изображений.

Первый экран выбрать за 20 минут; не делать 10 вариантов. Перенос в React сохраняет действующие API и авторизацию. Изменения доменной схемы из визуального макета не принимаются автоматически. Пока дизайн готовится, интерфейс развивается на тех же компонентах и fixture.
